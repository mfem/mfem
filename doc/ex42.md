# Example 42: ideal magnetohydrodynamics

Example 42 uses discontinuous Galerkin elements and a Rusanov flux for ideal
MHD. Optional Godunov-Powell volume and face terms (`-gp`) account for magnetic
divergence. On affine triangles and bilinear quadrilaterals, `-ldf` projects
the initial magnetic field and each magnetic time derivative into a locally
divergence-free space. Normal magnetic traces can still jump across faces.
There is no positivity limiter.

Build with `make ex42` and run from the examples directory.

## Orszag-Tang vortex (`-p 1`, default)

This nonlinear two-dimensional problem develops shocks. The defaults provide
a short-time demonstration, not a full shock evolution:

```sh
./ex42 -p 1 -r 1 -o 2 -tf 0.05 -c 0.2 -gp -ldf -no-vis
```

The reported L2 difference from the initial condition is not an error against
an exact solution. Longer runs can produce negative density or pressure
without a suitable limiter.

## Circularly polarized Alfven wave (`-p 2`)

This setup follows [Wu and Shu, arXiv:2604.23885v2, Section 4.1](https://arxiv.org/html/2604.23885v2#S4.SS1).
The angle is alpha = pi/6, rho = 1, p = 0.1, gamma = 5/3, and the periodic
rectangle is [0, 1/cos(alpha)] x [0, 1/sin(alpha)] = [0, 2/sqrt(3)] x [0, 2].
The default mesh has 4 x 4 uniform quadrilateral cells before refinement.
The primitive variables at time t are

```
ca = cos(alpha), sa = sin(alpha)
phi = 2*pi*(x*ca + y*sa + t)
b = 0.1*sin(phi), z = 0.1*cos(phi)
v = (-b*sa, b*ca, z)
B = (ca-b*sa, sa+b*ca, z)
E = 0.1/(gamma-1) + 1/2 + 0.01
```

The transverse velocity and magnetic perturbations have the same sign, so
the wave travels in the negative parallel direction. Its wavelength and
Alfven speed along that direction are both one, giving period one. With
`-p 2`, omitting `-tf` selects **T=1, one period**, as requested here; the paper
runs to T=5, five periods. An explicit `-tf` still overrides this default.

All eight conserved components are used on a 2D mesh (2.5D MHD).
`MHDdim` counts velocity and magnetic components independently of the mesh
dimension, with `mesh_dim <= MHDdim <= 3`. With `-ldf`, only B_x and B_y are
projected; B_z does not enter the two-dimensional divergence constraint.
Custom meshes supplied by `-m` should use the same periodic rectangle.

For a convergence study, keep the degree fixed and refine uniformly:

```sh
for r in 1 2 3; do
    ./ex42 -p 2 -r "$r" -o 2 -s 3 -tf 1 -c 0.2 -gp -ldf -no-vis
done
```

The cell count per direction is N = 4*2^r (8, 16, 32 above).
Each uniform refinement halves h. The reported `B_perp L2 error` uses
B_perp = -B_x*sin(alpha)+B_y*cos(alpha), matching the quantity in Table 4.1.
The full-state `L2 error against exact solution` is also reported. Both use
the actual final time. For either error, calculate `log(error_coarse/error_fine)/log(2)`. Degree p should approach
spatial order p+1 when temporal error is negligible. For degree 2, SSPRK3
(`-s 3`) also has order 3, so this study measures the fully discrete
convergence rate. Reduce the time step to isolate the spatial error. Repeat with half
the CFL or time step to assess temporal contamination. This example retains
its existing Rusanov DG discretization; adopting the benchmark data does not
implement the paper's complete PP-ES-DG method or reproduce its table directly.

A positive `-dt` selects fixed steps regardless of `-c`. For example,
`-tf 0.005 -dt 0.001 -vs 1` takes five steps; the final step is shortened when
needed. Otherwise a positive CFL number is required.

## Recorded convergence results: Intel/OpenMP, k=2, SSPRK3

Measured on 2026-10-16 in WSL2 (Linux 6.18.54.1-microsoft-standard-WSL2),
using Intel oneAPI C++ compiler `icpx` 2026.1.1, MFEM 4.10.1, double precision,
and a Release build (`-O3 -DNDEBUG -fiopenmp`). OpenMP and thread safety were
enabled; MPI and METIS were disabled.

All runs below use the Section 4.1 wave data above, degree **k=2**, **SSPRK3**
(`-s 3`), **GP sources and LDF projection enabled**, CFL **0.2**, and final time
**T=1 (one period)**. The meshes have N x N uniform quadrilateral cells and
`72*N*N` total state DOFs. Every run completed at T=1 and used six OpenMP
threads. The refinement rate is `log2(error_coarse/error_fine)`.

| N | State DOFs | B_perp L2 error | Rate | Full-state L2 error | Rate | Steps | Integration time (s) |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 8 | 4,608 | 5.59646567e-04 | — | 3.98604635e-03 | — | 206 | 2.164 |
| 16 | 18,432 | 6.46656753e-05 | 3.113 | 5.75148745e-04 | 2.793 | 411 | 16.584 |
| 32 | 73,728 | 8.07645320e-06 | 3.001 | 7.29380301e-05 | 2.979 | 821 | 159.910 |

The last refinement gives order **3.001** for B_perp and **2.979** for the
full state, consistent with third-order fully discrete convergence. These
results use the current Rusanov DG method and one period; they are not a
reproduction of the paper's five-period PP-ES-DG results.

Integration times are the wall-clock times printed by ex42 and exclude mesh
setup, initial projection, file output, and final error evaluation. OpenMP
parallelizes the element inverse-mass and LDF projection loops; the current
NonlinearForm volume/face residual assembly remains serial, so these timings
should not be interpreted as a sixfold speedup.

To reproduce the build, run from the repository root:

```sh
source /opt/intel/oneapi/setvars.sh
cmake -S . -B /tmp/mfem-dgmhd-intel-omp \
    -DCMAKE_CXX_COMPILER=icpx -DCMAKE_BUILD_TYPE=Release \
    -DMFEM_USE_MPI=OFF -DMFEM_USE_METIS=OFF \
    -DMFEM_THREAD_SAFE=ON -DMFEM_USE_OPENMP=ON \
    -DMFEM_USE_LEGACY_OPENMP=ON \
    -DMFEM_ENABLE_EXAMPLES=ON -DMFEM_ENABLE_TESTING=OFF \
    -DMFEM_ENABLE_MINIAPPS=OFF
cmake --build /tmp/mfem-dgmhd-intel-omp --target ex42 -j 6
```

Run each refinement in its own output directory:

```sh
source /opt/intel/oneapi/setvars.sh
export OMP_NUM_THREADS=6
export OMP_PROC_BIND=close
export OMP_PLACES=cores
export OMP_DYNAMIC=FALSE
unset KMP_BLOCKTIME  # use Intel's default waiting policy

for r in 1 2 3; do
    mkdir -p "/tmp/ex42-intel-convergence/convergence_r${r}"
    (
        cd "/tmp/ex42-intel-convergence/convergence_r${r}"
        /tmp/mfem-dgmhd-intel-omp/examples/ex42 \
            -p 2 -r "$r" -o 2 -s 3 -tf 1 -c 0.2 \
            -gp -ldf -no-vis -vs 1000000 > output.log 2>&1
    )
done
```

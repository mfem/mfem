# Miniapp: Hybridizable Discontinuous Galerkin

Drivers for `fem/darcy` — `DarcyForm`, `DarcyHybridization` and the two
reductions — on mixed problems in a flux `q`, a potential `u` and, where the
system is hybridized, a trace `λ` on the mesh skeleton.

This file is an index. **Each miniapp's own header comment is the reference
for that miniapp** — the formulation it discretises, what its options mean,
what has been verified about it and to what tolerance. Nothing here is
repeated from there.

## The miniapps

| | what it is for |
|---|---|
| `convdiff` / `pconvdiff` | convection-diffusion, and the workhorse. Ten problems (`-p 1`..`9` and `11`; `10` belongs to a sibling branch), linear and nonlinear, steady and transient. Everything the regression suite covers is one of these two. |
| `anisodiff` / `panisodiff` | asymptotic heat diffusion with an anisotropic conductivity whose symmetric and antisymmetric parts are separately adjustable, plus `h`-adaptivity (`-amr`) driven by `HDGErrorEstimator` through a `ThresholdRefiner`. |
| `anisodiff-hr` | `anisodiff` plus **`r`-adaptivity**: the mesh nodes are moved by a TMOP solve between refinements (`-ts` scales it). Serial only. Its header is otherwise a copy of `anisodiff`'s. |
| `navierstokes` / `pnavierstokes` | steady incompressible Navier-Stokes by the HDG method of Peraire, Nguyen & Cockburn in artificial-compressibility variables. NPC-driven; does not use `DarcyOperator`. |
| `mfem-logo` | convection-diffusion on a logo-shaped coefficient. A smoke test with pictures. |
| `hdgperf` | host performance harness: one hard problem, every host performance axis, and a ledger of which route each stage took. |
| `hdgdevice` | the device counterpart: which stages of the hybridized solve actually run on the device, and where the data still comes back. |

## Building

```
make convdiff              # or any target below
make                       # everything this configuration supports
```

Three of them drop out of the build rather than failing in it, and the
makefile says why at each:

* `navierstokes` and `pnavierstokes` need `MFEM_USE_SUNDIALS=YES` — they take
  their globalisation from KINSOL's `KIN_LINESEARCH` rather than carrying a
  line search, and `#error` without it. An MPI build needs an MPI-enabled
  SUNDIALS.
* `hdgdevice` is built only under `MFEM_USE_CUDA=YES`. In a host build every
  setting it turns on is a different route to the same loops, so its ledger
  would say "host" on every line.

`make test` runs the smoke targets (`convdiff-test-seq`,
`navierstokes-test-seq`, …), which grade on the **exit code alone**. Where a
miniapp has a sharp numerical property the target passes `-chk` so that
something actually checks it — plane Poiseuille at order ≥ 2 has a degree-2
exact solution that lies in the discrete space, so its errors come back at
round-off, and without `-chk` nothing would notice if they stopped.

## The regression suite

Richer than `make test`: it re-runs a recorded command line and compares the
solver string, the iteration counts and the two error norms.

```
cd miniapps/hdg && make convdiff && python3 regression_test.py
python3 regression_test.py -par                  # from the parallel build dir
python3 regression_test.py regress_test/p1_o2_hb_nl.txt    # one case, BY PATH
```

Four things about it are not guessable and each has cost someone time:

* **`regress_test/` and `regress_test_par/` are the upstream reference set**,
  recorded on their author's configuration. Some of them cannot reproduce
  exactly here; that is not a defect and they are not ours to rewrite.
* **`regress_test_local/` and `regress_test_par_local/` are gitignored and
  shadow them by filename.** `python3 regression_test.py --update-local`
  regenerates this machine's own copy of whatever genuinely drifts. A tracked
  case with no local file is compared exactly as before, so the local set
  cannot hide a regression in a case that was fine. The script prints how many
  references came from the local directory — **read that line before reading
  the failure count.**
* **The local directory is branch-independent**, because git does not manage
  an ignored path. Switching branches carries the previous branch's local
  references across, and they were generated by a different binary.
* **The command is rebuilt from a fixed option list, not from the recorded
  line.** A new miniapp flag has to be taught to the script or the reference
  is silently re-run without it. After generating a reference, perturb it and
  require a failure — a reference that is *skipped* reads exactly like one
  that passed.

`-prec` exists because the preconditioner used to be a compile-time choice, so
a build could not reproduce a reference that recorded the other one. `0` is
the build's own and the default.

## Where the rest of it is written

* the library's contracts and measurements — doxygen in `fem/darcy`
* a finding about one piece of code — a comment in that file
* how a miniapp is used, or how it works — the miniapp's own header comment,
  and this file for the map between them

`doc/*.md` in this tree is development scratch and is not documentation.
